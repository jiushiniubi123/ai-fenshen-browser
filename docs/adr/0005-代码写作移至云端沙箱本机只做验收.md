# 0005 - 代码写作移至云端沙箱，本机只做构建与验收

日期：2026-09-12（同日修订：验收路线由真机改为模拟器，真机仅用户人工验收——对齐用户级记忆）｜ 状态：已接受

GLM 配额是硬约束（用户级记忆：必须省着花），代码写作放到 Z.ai 网页版（agent 模式 + 沙箱 + GLM-5.3）完成，产物经 Git 回流。沙箱无 Android SDK、性能受限，构建必然失败；而验收标准（一条命令出 APK、模拟器可看网页）只能在本机满足。因此定下：**GitHub 仓库是唯一事实源**——术语表、ADR、agent 约定、构建配方、接力棒（NEXT.md）、代码全部入库，云端与本机读写同一份，不存在第二副本。分工：云端沙箱＝按 `docs/build-recipe.md` 钉死的版本盲写作，禁止执行构建；本机＝pull → `gradle assembleDebug` → 模拟器验收（AVD aifenshen；iQOO 真机不做自动验证靶机，仅留给用户人工验收）→ 关 issue。matt skills 与 ZCode 插件只在本机存在，涉技能的流程（triage / wayfinder / code-review / implement…）一律本机执行，云端只产出代码与文档。

## Considered Options

- **全在本机 ZCode 做**：体验最好但烧配额，被否（额度是硬约束）。
- **云端沙箱连构建也做**：无 SDK、下载量以 GB 计、性能差，必失败白烧时间，被否。
- **云端单独维护一套文档副本**：两份记忆必然漂移，被否——单一事实源。
