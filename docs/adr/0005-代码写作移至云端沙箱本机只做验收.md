# 0005 - 代码写作移至云端沙箱，本机只做构建与验收

日期：2026-09-12 ｜ 状态：已接受

GLM 配额是硬约束（用户级记忆：必须省着花），代码写作放到 Z.ai 网页版（agent 模式 + 沙箱 + GLM-5.3）完成，产物经 Git 回流。沙箱无 Android SDK、性能受限，构建必然失败；而验收标准（一条命令出 APK、真机可看网页）只能在本机满足。因此定下：**GitHub 仓库是唯一事实源**——术语表、ADR、agent 约定、构建配方、接力棒（NEXT.md）、代码全部入库，云端与本机读写同一份，不存在第二副本。分工：云端沙箱＝按 `docs/build-recipe.md` 钉死的版本盲写作，禁止执行构建；本机＝pull → `gradle assembleDebug` → 真机验收 → 关 issue。matt skills 与 ZCode 插件只在本机存在，涉技能的流程（triage / wayfinder / code-review / implement…）一律本机执行，云端只产出代码与文档。

**凭证策略**：云端默认**零凭证**——任务书（存 `.scratch/`）内联全部必需记忆要点，产物以 zip 回流、本机 commit + push，仓库地址对沙箱可提可不提。仅当改走仓库直连（clone/push）时才提仓库地址，并由用户签发**细粒度临时 token**（仅此一个仓库、仅 Contents 读写、短期有效、用完立即吊销）；绝不向云端提供主账号密码或长期 token。仓库是私有的，无凭证时沙箱不可见。

## Considered Options

- **全在本机 ZCode 做**：体验最好但烧配额，被否（额度是硬约束）。
- **云端沙箱连构建也做**：无 SDK、下载量以 GB 计、性能差，必失败白烧时间，被否。
- **云端单独维护一套文档副本**：两份记忆必然漂移，被否——单一事实源。
