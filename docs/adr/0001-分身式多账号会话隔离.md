# 0001 - 多账号采用"分身式"会话隔离

日期：2026-09-11 ｜ 状态：已接受

用户在主力网站上有多个账号，需要同时保持登录、随时切换。决定：每个账号做成一个**分身**——完全隔离的会话存储（cookie、localStorage 等网站数据互不共享），分身数量不限、可同时挂登录状态，切换互不踢下线。

## Considered Options

- **换人式全局切换**（同一时间只登一个号）：不能并行挂号，来回重登成本高，被否。
- **Firefox 容器（Containers）扩展**：桌面版功能，Android/GeckoView 端不可用（待技术调研最终确认），被否。
- **手机厂商的"应用分身/双开"**：只能复制整个 App，无法按账号隔离，体验割裂，被否。

## Consequences

- 底层必须有会话级隔离机制（候选：GeckoView 的 session context；具体机制待技术调研敲定后另立 ADR）。
- 每个分身的登录数据需按分身持久化保存；UI 需要分身切换器。
