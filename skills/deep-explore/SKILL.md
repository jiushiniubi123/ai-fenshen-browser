# deep-explore

> 流程：grilling 追问 → 确认画像 →（静默）搜索 → 审计 loop → HTML 报告。
> 报告模板见 `references/report-template.html`——进入第 5 步时读取，此前不加载。

## 1. grilling 式追问（第一个动作，与用户交互）

把研究需求映射成一棵 design tree：每个 decision（研究方向、知识水平、目标用途、使用场景、时效与地域范围、报告语言）都是一个分支。按轮处理，每轮问完整条 frontier——prerequisite 已敲定、现在就能问的那些问题；依赖未决答案的问题留到下一轮。

每个问题的格式：

```
❓ **Q1** - **<问题标题>**：<问题正文，含选项>

➡️ <你的推荐答案>
```

- 每轮用户回答后重算 frontier，再问下一轮。
- 环境 facts（行业数据、概念定义等）自己用搜索查，只把 decisions 交给用户。
- 逃生门：用户表示赶时间或不耐烦 → 用推荐答案补齐未决维度，直接进第 2 步。

**完成标志**：四个直接维度（研究方向、知识水平、目标用途、报告语言）均有值，且你能用一段话复述「用户是谁、要什么、为什么、怎么用」。

## 2. 确认展示（最后一个交互点）

输出一段话画像 + 报告将覆盖的 3-5 个章节方向，请用户确认或微调。确认后进入**静默**：只调用工具、读写文件，不再对用户输出文字，直到报告完成。

**完成标志**：用户确认画像与章节方向。

## 3. 搜索（3 路并行子代理，同批启动）

| 方向 | 覆盖内容 |
|------|---------|
| BROAD | 概览、定义、行业背景 |
| DEEP | 机制、技术细节、一手来源 |
| REVERSE | 反面观点、批评、风险、局限 |

来源规则（一手优先，非一手分级可用）：

- 每个关键事实先找**拥有该事实的 source**：官方文档、论文、源码、官方统计。
- 非一手来源按 **T1 权威**（官方/学术/标准）、**T2 专业媒体**（行业报告、专业分析）、**T3 社区**（知乎、Reddit、博客）分级标注；T3 只承载观点与舆情，事实声明必须由 T1/T2 支撑。
- 每个 claim 记录来源 URL 与等级。
- 每方向 3-5 个来源；单方向不足 3 个时换搜索词重试一次，仍不足标注「来源稀缺」。

**完成标志**：三路结果全部落盘，每个 claim 带来源 URL 与 T 等级。

## 4. 分析与审计（一个 tight loop）

1. **综合**（主 agent）：合并三路结果，列出主题的全部关键维度，逐一标注 已覆盖 / 部分覆盖 / 缺失；产出拟入报告的事实声明清单。
2. **独立审计**（一个子代理，必须）：输入仅搜索结果 + 声明清单——不含你的综合叙述，审计者在新鲜 context 中验证，避免被你的推理锚定。逐条标注：可溯源（指出支撑来源）/ 不可溯源（降级为「观点」或剔除）/ 矛盾（来源间数据冲突）；同时检查关键来源的商业利益与立场偏见。
3. **领域视角**（条件 branch）：grilling 阶段判定为强专业领域（医疗、法律、金融合规等）时，增加一个领域视角子代理——输入仅搜索结果与本轮引导问题，产出该领域特有的风险与判断；通用话题跳过此步。
4. **缺口驱动**：存在关键维度缺失或未解事实冲突 → 针对缺口补搜一轮，回到 1；无关键缺口 → 进第 5 步。

**完成标志**：全部关键维度已覆盖或显式标注稀缺；每条入报告的事实声明均经审计子代理逐条验证。

## 5. 生成 HTML 报告

读取 `references/report-template.html`，填充为**单个自包含 HTML 文件**（CSS 内联，无外部依赖）：

- 正文 1500-3000 字——写满信息密度，不凑字数，章节数由研究发现驱动。
- 深度对齐画像知识水平：零基础 → 每个术语配一句通俗解释；专家 → 跳过基础直给结论与争议。
- 事实声明句内以上标链接标注来源；观点与事实分开陈述。
- 文末列来源清单（按 T1/T2/T3 分组）与「来源稀缺 / 待验证」声明（有则列，无则省）。
- 文件名贴合主题，如 `量子计算商业化_深度探索.html`，保存后用 present_files 交付。

**完成标志**：HTML 可独立打开；篇幅达标；事实句均有来源标注；稀缺声明已列出。
